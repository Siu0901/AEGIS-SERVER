# AEGIS 임베디드 연동 명세서

Jetson Orin Nano(Tier 0)와 ESP32(경고 장치)가 서버에 붙기 위해 구현해야 하는 것 전량.

**v1 · 2026-08-02 · 대상 마일스톤 M9**

---

## 0. 이 문서의 위치

**이 문서는 파생 문서다. SSOT는 `docs/AEGIS_API명세서.md` 다.**

여기 있는 내용은 전부 API명세서 §1~§3·§6 과 기능명세서 §4.1 에서 옮긴 것이며,
임베디드 쪽이 필요한 것만 모아 순서를 바꿨을 뿐이다. **충돌하면 API명세서가 맞다.**
필드를 하나라도 고쳐야 한다고 판단되면 이 문서가 아니라 API명세서를 고치고,
그 전에 사람에게 보고한다(CLAUDE.md 절대규칙 8).

스키마의 실제 구현은 `packages/contracts` 하나이며, 서버·시뮬레이터·프론트가 전부
그것을 import 한다(절대규칙 5). 파이썬으로 엣지를 짠다면 **이 패키지를 그대로 쓰면
필드 실수가 컴파일 시점에 드러난다.**

| 참조 | 위치 |
|---|---|
| 엣지 → 서버 메시지 4종 | API명세서 §2 |
| MQTT 페이로드 2종 | API명세서 §3 |
| 필드 산출법(접지점·자세·거리·분류) | API명세서 §6 |
| 감지 기능 요구사항 FN-DET-01~12 | 기능명세서 §4.1 |
| 계약 코드 | `packages/contracts/src/aegis_contracts/edge.py` · `mqtt.py` |
| 참조 구현(가짜 엣지·가짜 MCU) | `sim/edge_sim/` · `sim/mcu_sim/` |

## 1. 연결 대상

| 장치 | 방향 | 프로토콜 | 엔드포인트 |
|---|---|---|---|
| Jetson (엣지) | 엣지 → 서버 | WebSocket | `ws://<server>:8000/ws/edge` |
| ESP32 (경고 장치) | 서버 → 장치 | MQTT 구독 | `aegis/alert` |
| ESP32 (경고 장치) | 장치 → 서버 | MQTT 발행 | `aegis/device/status` |

브로커는 현장 내 mosquitto(`<server>:1883`)다. **서버는 엣지에게 아무것도 보내지
않는다** — `/ws/edge` 는 단방향이다.

## 2. 공통 규약 (양쪽 모두)

### 2.1 좌표는 두 종류뿐이다

| 종류 | 표기 | 정의 |
|---|---|---|
| 정규화 픽셀 | **접미사 없음**, 0.0~1.0 | 프레임 좌상단 원점, 우·하가 양수. 해상도로 나눈 비율 |
| 지면 실좌표 | **접미사 `_m`**, 미터 | 캘리브레이션 원점 기준 현장 평면 좌표 |

- bbox 는 `[x1, y1, x2, y2]` (좌상단, 우하단, 정규화)
- 거리는 미터, 소수점 둘째 자리
- 접미사 규칙이 곧 단위 표시다. `foot_point` 와 `foot_point_m` 은 **다른 값**이다

### 2.2 화면비 제약 — 어기면 오버레이가 통째로 어긋난다

엣지는 **서브**(640×360)에서 좌표를 뽑지만 대시보드는 그 좌표를 **메인**(1920×1080)
위에 그린다. 정규화 좌표라서 해상도는 달라도 되지만 **화면비는 같아야 한다.**

| 스트림 | 해상도 | 화면비 | 코덱 | fps | 받는 쪽 |
|---|---|---|---|---|---|
| 메인 | 1920×1080 | 16:9 | H.264 | 15 | 서버 (라이브·녹화·클립) |
| 서브 | 640×360 | **16:9 (동일)** | H.264 | 15 | 엣지 (추론) |

**서브를 640×640 같은 정사각으로 설정하지 않는다.** 정사각화가 필요하면 카메라가
아니라 **모델 입력 단계의 레터박스**(640×384 rect)에서 처리한다.

### 2.3 시각

- ISO 8601 **UTC**, 밀리초 포함 (`2026-08-14T05:37:02.183Z`)
- 저장·전송은 UTC, 표시만 KST
- `frame.ts` 는 **프레임 촬영 시각**이다. 서버가 이 값으로 녹화 링버퍼에서 클립을
  잘라내므로 **NTP 동기화가 전제**다 (§3.4.4 하트비트 `clock` 참조)

### 2.4 `track_id`

- **카메라 안에서만 유효**하다. 전역 식별은 `cam_id` 와 조합한다
- **`person` 과 `vehicle` 모두에 부여한다.** 지게차에 track_id 가 없으면 뎁스 캐시
  키(`cam_id + 사람 track_id + 지게차 track_id`)를 만들 수 없다

### 2.5 알 수 없는 필드는 거부된다

계약 모델이 `extra="forbid"` 다. **명세서에 없는 필드를 실어 보내면 그 메시지 전체가
거부된다.** 디버그용 필드를 임시로 얹지 마라 — 그 프레임의 좌표가 통째로 사라진다.

## 3. Jetson (엣지) 연동

### 3.1 엣지가 하지 않는 것 — 이것이 가장 중요하다

> **엣지는 판단하지 않는다. 후보만 올린다.** (CLAUDE.md 절대규칙 3)

| 엣지가 하는 것 | 서버가 하는 것 |
|---|---|
| 감지·추적·크롭 분류 | **확정** 판정 (3초 연속 관측) |
| 좌표 변환(호모그래피)·거리·자세 계산 | **경고 발동** (스피커·경광등) |
| 규칙 충족 시 `candidate` 전송 | **시정 판정** (10초 해소 관측) |
| | 재결합·판정 불가·쿨다운·지표 |

엣지가 「이건 확정이다」라고 판단하거나, 확정 여부에 따라 전송을 바꾸면 서버의
상태머신 검증이 전부 무의미해진다. 규칙에 걸리면 **매번 후보를 올리고 끝낸다.**

또한 엣지는 **영상과 마스크를 서버로 보내지 않는다.** 마스크는 접지점·최근접 거리·
자세 판정에 쓰고 **결과값만** 싣는다. 영상은 카메라 메인 스트림을 서버가 직접 받는다.

### 3.2 카메라에서 무엇을 받는가

**카메라 한 대가 스트림 두 개를 동시에 내보낸다.** 카메라를 나눠 다는 것이
아니라, **같은 카메라의 메인·서브를 서버와 엣지가 각각 구독**한다.

```
                  ┌── main 1920×1080 ──┬─▶ 서버   (라이브 재스트리밍)
   IP 카메라 ──────┤                    └─▶ REC    (7일 세그먼트 녹화)
   (cam_id: 1)    └── sub   640×360 ─────▶ 젯슨   (추론)
```

카메라 2대면 스트림은 넷이고, 메인은 각각 **두 곳이 독립 구독**한다
(2.5Mbps × 2대 × 2구독 = 10Mbps · 유선 LAN 기준 여유).

| 스트림 | 규격 | 구독자 | 용도 |
|---|---|---|---|
| `main` | 1920×1080 · H.264 · 15fps · 약 2.5Mbps | 서버 + REC | 라이브 · 녹화 · 클립 원본 · 키프레임 |
| `sub` | **640×360** · H.264 · 15fps | **엣지** | 추론 |

> ★ **엣지는 메인을 건드리지 않는다.** 추론은 서브만 본다. 반대로 **엣지가 영상을
> 서버로 중계하지도 않는다** — 서버는 카메라에서 직접 받는다. 엣지가 서버로 보내는
> 것은 메타데이터(§3.4)뿐이다.

**카메라 쪽 설정 요구**

- 듀얼 스트림(멀티 프로파일)을 **동시 송출**할 수 있어야 한다
- 두 스트림의 화면비가 **16:9 로 같아야 한다**(§2.2). 서브를 640×640 같은 정사각으로
  두면 화각이 잘리거나 정규화 좌표가 눌린다
- 서브를 640×360 **미만**으로 낮추지 않는다 — `cls_min_crop_px`(기본 64px) 게이트를
  통과하려면 사람이 **프레임 높이의 약 18% 이상**을 차지해야 하고, 해상도를 더 낮추면
  그 조건이 더 까다로워져 원거리 작업자의 안전모 판정이 계속 보류된다
- 카메라 시계와 무관하게 **`frame.ts` 는 엣지가 찍는다**(§2.3). 카메라 OSD 타임스탬프에
  의존하지 않는다

**RTSP 주소는 어디서 오는가**

DB `cameras` 테이블이 `rtsp_main` · `rtsp_sub` 를 들고 있고 `GET /api/v1/cameras`
(§4.5)가 `cam_id` · `name` 과 함께 내보낸다. 개발 환경의 경로 규약은 이렇다:

```
{RTSP_BASE}/cam1/main    1920×1080 15fps H.264 2.5Mbps   → 서버 · REC
{RTSP_BASE}/cam1/sub       640×360 15fps H.264           → 엣지
```

⚠ **지금은 원천이 둘이다.** `edge/config.yaml` 의 `streams[].rtsp_sub` 에도 같은 주소가
적혀 있다. 카메라를 교체하거나 IP 가 바뀌면 설정 화면에서 고친 값과 엣지가 보는 값이
갈리고, 그 어긋남은 **엣지가 옛 주소로 재연결을 반복하는 모습**으로만 드러난다.
정책 수신 경로(§3.9)와 같은 사안이므로 함께 정해야 한다 —
`docs/INDEX.md` 「명세서 확인 필요」.

**`cam_id` 는 엣지가 정하지 않는다.** DB `cameras.cam_id` 가 원천이며, 캘리브레이션·
구역·이벤트가 전부 이 번호에 걸려 있다. 엣지는 자기가 구독하는 스트림이 어느
`cam_id` 인지 알고 있어야 하고, 그 값을 `frame` · `candidate` · `track_lost` ·
`heartbeat.cameras[]` 에 그대로 싣는다.

**스트림이 끊기면**

- 재연결을 시도하되 **하트비트는 계속 보낸다.** 그 카메라의 `sub_state` 를
  `reconnecting` → 복구 실패 시 `down` 으로 싣는다
- 하트비트까지 멈추면 서버는 **엣지 전체**가 죽은 것으로 보고 모든 카메라의 서브를
  `down` 으로 내린다 — 카메라 한 대만 끊긴 것과 구분되지 않게 된다
- 메인 스트림 상태는 **서버가 따로 관측한다**(mediamtx 폴링). 엣지가 보고하지 않는다

### 3.3 서버 접속과 재전송

- `ws://<server>:8000/ws/edge` 에 접속해 JSON 텍스트 프레임으로 보낸다
- **단방향이다.** 서버는 ACK·NACK 을 보내지 않는다
- **재전송하지 않는다.** 스키마 불일치는 일시적 장애가 아니라 엣지 코드의 결함이라
  재전송해도 같은 결과가 반복되고, 실시간 루프에 재시도 대기를 넣으면 지연만 늘어난다.
  유실은 다음 프레임으로 자연히 복구된다
- 연결이 끊기면 재접속한다. 서버는 끊긴 순간 엣지를 `down` 으로, 모든 카메라의
  **서브 스트림을 `down`** 으로 내린다(관측 주체가 없으므로)

### 3.4 보내야 하는 메시지 4종

| `type` | 언제 | 주기 |
|---|---|---|
| `frame` | 매 프레임 | **카메라당 8fps 이상** |
| `candidate` | 위반 규칙 충족 시 | 조건이 유지되는 동안 계속 |
| `track_lost` | 트랙을 최종 포기했을 때 | 1회 |
| `heartbeat` | 상태 보고 | **5초** |

**필수·선택 규약** — 아래 표에서 `·생략` 표기가 있는 필드만 선택이고 나머지는 전부
필수다. `·null` 표기는 **필드 자체는 항상 싣고 값만 `null`** 이 될 수 있다는 뜻이다.
이 둘은 다르다: 빠진 것과 없는 것이 같아 보이면 안 되는 자리들이다.

#### 3.4.1 `frame` — 프레임 메타데이터 (API명세서 §2.1)

```json
{
  "type": "frame",
  "cam_id": 1,
  "ts": "2026-08-14T05:37:02.183Z",
  "objects": [
    {
      "class": "person",
      "track_id": 3,
      "conf": 0.91,
      "bbox": [0.197, 0.364, 0.273, 0.764],
      "helmet": "off",
      "helmet_conf": 0.88,
      "helmet_checked_at": "2026-08-14T05:37:01.900Z",
      "foot_point": [0.235, 0.762],
      "foot_point_m": [4.21, 7.85],
      "foot_conf": 0.88,
      "posture": "standing",
      "height_ratio": 0.97,
      "axis_angle_deg": 8.2,
      "stillness_s": 0.4,
      "in_zone": "forklift_lane",
      "nearby": [
        { "track_id": 11, "class": "vehicle", "dist_m": 1.55,
          "basis": "mask_nearest", "in_danger_zone": true }
      ]
    },
    {
      "class": "vehicle",
      "track_id": 11,
      "conf": 0.87,
      "bbox": [0.591, 0.389, 0.838, 0.756],
      "anchor": [0.714, 0.754],
      "anchor_m": [7.02, 8.90],
      "moving": true,
      "danger_radius_m": 3.0
    }
  ]
}
```

**공통** — `cam_id`(int) · `ts`(string) · `objects[]`

`objects[].class` 는 **`person` 또는 `vehicle` 둘뿐**이다. 안전모 클래스는 없다.

**person 필드**

| 필드 | 타입 | 설명 |
|---|---|---|
| `track_id` · `conf` · `bbox` | int · float · float[4] | 감지 결과 |
| `helmet` | `on`/`off`·생략 | 2단계 분류 결과. **두 값뿐이며 `unknown` 은 없다** |
| `helmet_conf` | float·생략 | `helmet` 이 실린 경우에만 함께 |
| `helmet_checked_at` | string·생략 | 분류를 **채택**한 시각. `helmet` 과 한 묶음 |
| `foot_point` | float[2] | 접지점 정규화 좌표 (§6.1) |
| `foot_point_m` | float[2] | 접지점 지면 실좌표 (§6.2) |
| `foot_conf` | float | 접지점 신뢰도. 낮으면 뎁스 트리거 C |
| `posture` | `standing`/`fallen`/`unknown` | 자세 (§6.4) |
| `height_ratio` | float | 마스크 높이 ÷ 그 거리의 기대 높이 |
| `axis_angle_deg` | float | 마스크 주축과 화면 수직축의 각(도) |
| `stillness_s` | float | 정지 지속(초) |
| `in_zone` | string·**null** | 접지점이 든 구역 ID. 없으면 `null`, 필드는 항상 싣는다 |
| `nearby[]` | array | 차량과의 거리. 없으면 **빈 배열**, 필드는 항상 싣는다 |

**`nearby[]` 원소** — `track_id`(int) · `class`(`"vehicle"`) · `dist_m`(float) ·
`basis`(`mask_nearest`/`anchor`) · `in_danger_zone`(bool)

> ★ **`nearby` 를 빠뜨리면 진행 중인 근접 이벤트가 해소로 판정된다.**
> 서버는 이 값으로 `proximity` 해소를 판정한다. 필드가 없으면 「주변에 지게차가
> 없다」로 읽는다. 후보를 만들 때 이미 계산한 값이므로 추가 비용은 없다 —
> **확정과 해소는 반드시 같은 양을 보아야 한다.**

**vehicle 필드**

| 필드 | 타입 | 설명 |
|---|---|---|
| `track_id` · `conf` · `bbox` | int · float · float[4] | 감지 결과 |
| `anchor` | float[2] | 지면 기준점 **정규화 좌표**. 오버레이 거리선의 끝점 |
| `anchor_m` | float[2] | 위를 호모그래피로 변환한 지면 실좌표 |
| `moving` | bool | 최근 프레임 대비 이동 여부 |
| `danger_radius_m` | float | 그 클래스의 위험 반경 (서버 `vehicle_classes`, 기본 3.0) |

> ★ **`anchor` 는 bbox 아래변 중앙이 아니다.** 마스크 하단에서 산출한 값이라 포크가
> 뻗었거나 적재물이 있으면 박스 중앙과 어긋난다. 클라이언트가 bbox 로 추정하지
> 않도록 엣지가 반드시 싣는다.

#### 3.4.2 `candidate` — 이벤트 후보 (API명세서 §2.2)

```json
{
  "type": "candidate",
  "cam_id": 1,
  "ts": "2026-08-14T05:37:02.183Z",
  "track_id": 3,
  "violation_type": "no_helmet",
  "zone_id": "forklift_lane",
  "bbox": [0.197, 0.364, 0.273, 0.764],
  "conf": 0.91,
  "foot_point_m": [4.21, 7.85],
  "foot_conf": 0.88,
  "helmet": "off",
  "helmet_conf": 0.88,
  "posture": "standing",
  "observed_ms": 3200,
  "nearby": [
    { "class": "vehicle", "track_id": 11, "dist_m": 3.2, "method": "mask_nearest",
      "depth_verified": true, "moving": true, "within_danger_radius": true }
  ]
}
```

| 필드 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `violation_type` | string | ✔ | **단일 값.** `no_helmet`/`zone_intrusion`/`proximity`/`fall` |
| `track_id` | int | ✔ | 위반 대상 **사람**의 추적 번호 |
| `zone_id` | string·**null** | ✔ | 없으면 `null`, 필드는 항상 싣는다 |
| `bbox` · `conf` · `foot_point_m` | | ✔ | 대상 위치 |
| `observed_ms` | int | ✔ | **이 유형을** 연속 관측한 시간(ms) |
| `foot_conf` | float·생략 | | `fall` 처럼 접지점이 무의미하면 생략 |
| `helmet` · `helmet_conf` · `posture` | ·생략 | | 위반의 근거 |
| `nearby[]` | array | | 스크리닝 반경(기본 5m) 안의 지게차. 없으면 `[]` |

**`candidate.nearby[]` 는 `frame.nearby[]` 와 다른 모양이다.** 이쪽은 후보의 근거를
담으므로 `method` · `depth_verified` · `moving` · `within_danger_radius` 가 더 있다.

> ★ **한 트랙에 두 유형이 걸리면 메시지를 두 개 보낸다.** 배열이 아니다 —
> 이벤트 병합 키가 `cam_id + track_id + violation_type` 이고 유형마다 확정 타이머가
> 독립적으로 도는데, `observed_ms` 도 유형마다 값이 다르므로 하나로 담을 수 없다.

#### 3.4.3 `track_lost` — 트랙 소실 (API명세서 §2.3)

```json
{ "type": "track_lost", "cam_id": 1, "track_id": 3, "class": "person",
  "last_ts": "2026-08-14T05:37:09.410Z", "last_foot_point_m": [4.55, 7.90],
  "last_helmet": "off", "reason": "occluded" }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `class` | `person`/`vehicle` | 소실한 대상의 클래스 |
| `last_ts` | string | 마지막 관측 시각. **재결합 시간 창 Δt 의 기준** |
| `last_foot_point_m` | float[2] | 마지막 지면 좌표. **재결합 반경 판정의 기준점** |
| `last_helmet` | string·생략 | 소실 직전 분류 결과 |
| `reason` | `occluded`/`out_of_view`/`low_conf` | 진단용 |

> ★ **ByteTrack 버퍼로 복구되는 짧은 단절에는 보내지 않는다.** 엣지가 트랙을
> **최종적으로 포기한 시점**에만 1회 보낸다. 남발하면 서버가 매번 재결합 대기에
> 넣었다가 풀어 이벤트 수명이 실제와 달라진다.

#### 3.4.4 `heartbeat` — 상태 보고 5초 주기 (API명세서 §2.4)

```json
{
  "type": "heartbeat", "ts": "2026-08-14T05:37:05.000Z",
  "cameras": [
    { "cam_id": 1, "sub_state": "ok", "fps": 8.2 },
    { "cam_id": 2, "sub_state": "ok", "fps": 8.0 }
  ],
  "gpu_util": 0.41, "mem_used_mb": 3820,
  "cls_calls_per_min": 96, "cls_cache_hit_rate": 0.87, "depth_calls_per_min": 14,
  "clock": { "offset_ms": 12, "synced": true,
             "source": "pool.ntp.org", "last_sync_at": "2026-08-14T05:30:00Z" }
}
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `cameras[].sub_state` | `ok`/`reconnecting`/`down` | 엣지가 보는 **서브** 스트림 상태. `degraded` 는 없다 — 구성요소 상태(§5.3)와 다른 열거형이다 |
| `cameras[].fps` | float | 실제 처리 fps. **8 미만 지속 시 대시보드 경고** |
| `gpu_util` · `mem_used_mb` | float · int | 자원 |
| `cls_calls_per_min` · `cls_cache_hit_rate` | int · float | 2단계 분류 호출·캐시 적중률 |
| `depth_calls_per_min` | int | 뎁스 호출 빈도. 과다하면 회색지대 밴드 재조정 |
| `clock` | object·생략 | **시계 상태 — 아래 참조** |

**`clock` 절 (FN-SYS-02)**

| 필드 | 타입 | 설명 |
|---|---|---|
| `offset_ms` | float | 엣지가 **자체 NTP 로 측정한** 자기 시계 오차(ms) |
| `synced` | bool | NTP 동기화 성공 여부. **`false` 면 서버가 `offset_ms` 를 무시한다** |
| `source` | string·null | 동기 서버 |
| `last_sync_at` | string·null | 마지막 동기 시각 |

> ★ **서버가 도착 시각으로 추정하지 않고 엣지가 직접 보고한다.** 이 값의 용도는
> 「클립 추출 구간을 믿어도 되는가」 하나뿐인데, `ts` 와 도착 시각의 차이로 재면
> 네트워크 지연이 섞여 시계 오차와 전송 지연을 구분할 수 없다.
>
> 자기 신고의 약점(엣지 NTP 가 실패하면 틀린 값을 자신 있게 보고함)은 `synced` 로
> 막는다. **NTP 가 실패하면 `offset_ms` 를 0으로 채우지 말고 `synced: false` 로 보내라.**
> 서버는 그때 `edge_offset_ms` 를 `null` 로 전달하고 화면에 「시각 동기화 실패」를
> 경고로 띄운다.
>
> `|offset_ms|` 가 `clock_offset_warn_ms`(기본 100)를 넘으면 서버가
> `system`(`component:"edge"`, `state:"degraded"`)을 발행한다.

**시각이 어긋나면 무엇이 망가지는가**: 클립은 **정상적으로 생성되고 재생되지만
다른 구간을 담는다.** 사람이 영상을 열어보기 전까지 그 사실이 드러나지 않는다.
NTP 동기화가 엣지 구현의 필수 항목인 이유다.

### 3.5 필드 산출 책임 (API명세서 §6)

서버는 아래 값을 **다시 계산하지 않는다.** 엣지가 보낸 값을 그대로 쓴다.

| 값 | 산출 |
|---|---|
| `foot_point` | 사람 마스크 픽셀 중 **y 하위 8%** 띠의 **x 중앙값** → 정규화. bbox 하단 중앙은 초기 구현용이며 다리를 벌리면 어긋난다 |
| `foot_point_m` | 접지점에 카메라별 호모그래피 H 적용: `[X',Y',W] = H·[u,v,1]ᵀ` → `(X'/W, Y'/W)`. **카메라를 움직이면 재캘리브레이션** |
| `helmet` | person bbox 를 패딩 확장해 크롭 → 224×224 → 분류. 여러 사람은 **배치 1회 추론** |
| `posture` | `height_ratio` · `axis_angle_deg` · `stillness_s` **세 조건 모두** 충족해야 `fallen` |
| `axis_angle_deg` | 마스크 픽셀에 PCA → 주축과 화면 수직축의 각 |
| `stillness_s` | 마스크 **중심 이동량과 형태 변화량이 모두** 임계 이하인 지속 시간 |
| `nearby[].dist_m` | `mask_nearest` — 두 마스크 윤곽점을 각각 실좌표로 변환한 뒤 최소 거리 |
| `depth_verified` | 뎁스 1프레임으로 사람·지게차 영역의 **상대 깊이 분포 비교** |

**호모그래피 오용 주의**: 사람 마스크 **전체**를 지면으로 투영해 크기를 재지 마라.
지면 평면 가정 때문에 서 있는 사람의 상반신이 지면상 먼 지점으로 투영되어 **누운
사람보다 오히려 길게 나오는 역전**이 발생한다. 호모그래피는 **접지점 거리 산출에만**
쓴다.

**단안 뎁스 주의**: 절대 거리가 부정확하다. **거리 수치는 항상 호모그래피 값**을
쓰고, 뎁스는 앞뒤 분리 판별과 깊이 분산 확인에만 쓴다.

### 3.6 `helmet` 게이팅 — 세 경우를 구분해서 보내라 (§6.3)

| 상황 | `frame` 메시지 | 서버 처리 |
|---|---|---|
| 게이트 통과 | `helmet` 갱신 + `helmet_checked_at` 갱신 | 정상 판정 |
| 미통과 · 캐시 있음 | 직전 `helmet` 유지, **`helmet_checked_at` 은 갱신하지 않음** | 값이 오래됐음을 인지하고 타이머 **동결** |
| 미통과 · 캐시 없음 | **`helmet` 필드 생략** (3개 모두 생략) | `no_helmet` 후보를 만들지 않음 |

- 크롭 높이가 `cls_min_crop_px`(기본 64) 미만이면 **추론 자체를 생략**한다
- 결과 신뢰도가 `cls_min_conf`(기본 0.6) 미만이면 **채택하지 않는다**
- 채택된 결과를 `track_id` 별로 캐싱하고 `cls_cache_ms`(기본 1000) 동안 재사용한다

> **`unknown` 을 만들지 마라.** 분류 모델의 클래스는 `on`/`off` 2종뿐이다. 판정 불가는
> **필드 생략**으로 표현한다. 서버는 그 구간에서 확정·해소 타이머를 리셋하지 않고
> **동결**한다 — 작업자가 잠시 멀어졌다고 판정이 처음부터 다시 시작되면 조건이
> 영원히 충족되지 않는다.

### 3.7 뎁스 온디맨드 트리거 (FN-DET-11)

하나라도 충족하면 **1프레임** 실행한다.

| 트리거 | 조건 |
|---|---|
| A | 산출 거리가 **회색지대**(`depth_band_m`, 기본 2.0~3.5m)에 포함 |
| B | 두 객체의 화면상 영역이 겹침 (IoU > 0) |
| C | 접지점 신뢰도가 임계 미만 |
| D | 쓰러짐 3조건 충족 (자세 검증용) |

캐시 키는 `(cam_id, 사람 track_id, 지게차 track_id)` 이며 `depth_cache_ms`(기본 500)
동안 재사용한다. **어느 한쪽이 지면 좌표로 임계 이상 이동하면 즉시 무효화**한다.

### 3.8 스키마를 어기면 어떻게 되는가 (FN-SYS-06)

서버는 검증에 실패한 메시지를 **조용히 버리지 않는다.**

1. 원본 페이로드와 검증 오류를 `WARNING` 이상으로 로깅
2. `edge_msg_rejected_total{type, reason}` 카운터 증가
3. `GET /system/status` 와 **대시보드 개요·설정 화면에 거부 건수 노출**

즉 **엣지 구현이 틀리면 화면에 숫자로 드러난다.** 통합 시 이 값이 0인지 먼저 본다.

### 3.9 설정은 어디서 오는가

| 종류 | 위치 | 예 |
|---|---|---|
| **장비 종속** | `edge/config.yaml` | RTSP 주소, 모델 엔진 경로, `imgsz: [384, 640]`, 디코더 백엔드, 목표 fps |
| **판정 임계** | **서버 DB `policies`** | `cls_min_crop_px` · `cls_min_conf` · `cls_cache_ms` · `depth_band_m` · `depth_cache_ms` · `screening_radius_m` · `min_confidence` · `proximity_threshold_m` · `fall_height_ratio_max` · `fall_axis_angle_min_deg` · `fall_stillness_s` · `stillness_move_px` · `stillness_window_s` · `stillness_shape_change_max` |
| **위험 반경** | 서버 DB `vehicle_classes` | `danger_radius_m`(기본 3.0) |

> **임계값을 `config.yaml` 에 복사해 두지 마라.** 현장에서 화면으로 조정하는 값이며,
> 두 곳에 있으면 한쪽만 바뀐 채로 돈다(CLAUDE.md 절대규칙 6).

⚠ **정책을 엣지가 어떻게 받는지는 명세서에 정의되어 있지 않다.** 지금 존재하는 통로는
`GET /api/v1/policies`(§4.5) 하나뿐이며 그것은 대시보드용으로 정의된 것이다. 엣지가
주기적으로 폴링할지, `/ws/edge` 에 하행 메시지를 신설할지 **정해야 한다** —
`docs/INDEX.md` 「명세서 확인 필요」에 올려 두었다.

### 3.10 성능 요구

| 항목 | 값 |
|---|---|
| 처리량 | **카메라당 8fps 이상** |

## 4. ESP32 (경고 장치) 연동

### 4.1 구독 — `aegis/alert`

```json
{ "event_id": "EV-20260814-0231", "type": "no_helmet", "level": 2,
  "zone_id": "forklift_lane", "duration_s": 5, "repeat": false }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `event_id` | string | 자동 경고는 `EV-YYYYMMDD-NNNN`, **수동 방송은 `MANUAL-cam{N}-{ISO8601}`** |
| `type` | string | **점멸 패턴 선택자.** `no_helmet`/`zone_intrusion`/`proximity`/`fall`/**`manual`** |
| `level` | **1·2·3만** | 1=주의(부저 없음) · 2=경고 · 3=긴급(연속 부저) |
| `zone_id` | string·null | 구역 |
| `duration_s` | int | 경광등·부저 지속 시간 (서버 정책 `alert_duration_s`, 기본 5) |
| `repeat` | bool | 재경고. `true` 면 **패턴을 달리해** 상습 상황을 구분한다 |

- **`fall` 은 항상 `level: 3`** 이다. 서버가 3 미만으로 내려보내는 일은 없다
  (API 가 거부한다) — 장치도 이 가정을 깨는 방향으로 구현하지 않는다
- **`manual` 은 일반 주의 환기 패턴**으로 처리한다. 위반 유형 패턴을 빌려 쓰면
  실제 위반이 감지된 것처럼 동작한다. `event_id` 도 조회 가능한 이벤트가 아니다
- **지속 시간은 장치가 정하지 않는다.** `duration_s` 를 그대로 쓴다

**음성 방송은 ESP32 가 하지 않는다.** 스피커 방송은 서버가 사전 녹음 wav 를 재생한다
(TTS 아님). ESP32 는 **경광등·부저만** 담당한다.

### 4.2 발행 — `aegis/device/status`

```json
{ "device": "esp32-01", "online": true, "uptime_s": 84210,
  "last_alert": "2026-08-14T05:37:03Z" }
```

| 필드 | 타입 | 설명 |
|---|---|---|
| `device` | string | 장치 식별자 |
| `online` | bool | 자기 보고 |
| `uptime_s` | int | 기동 후 경과 |
| `last_alert` | string·null | 마지막으로 **수행한** 경고 시각. 없으면 `null` |

- 발행 주기 **10초** (참조 구현 `sim/mcu_sim` 기준)
- 서버는 이 보고가 **`MCU_STALE_AFTER_S`(기본 30초) 이상 끊기면 오프라인으로 본다.**
  주기 10초 × 3회 누락에 해당한다. 주기를 늘리려면 서버 설정도 함께 올려야 한다
- 브로커에 서버가 붙어 있다는 사실은 **장치가 살아 있다는 뜻이 아니다.** 그래서
  신선도로 판정한다

### 4.3 ESP32 가 하지 않는 것

- 경고 여부를 **판단하지 않는다.** 받은 명령만 수행한다
- 명령을 **저장·재생하지 않는다.** 놓친 경고를 나중에 울리면 현장이 혼란스러워진다
- 음성 방송을 하지 않는다 (4.1 참조)

## 5. 통합 검수 체크리스트

시뮬레이터가 **서버 입장에서 실물과 구분되지 않게** 만들어져 있다. 실물을 붙이기 전에
같은 검사를 통과하는지 대조한다.

### 5.1 엣지

- [ ] `/ws/edge` 접속 후 `GET /system/status` 의 `edge.online` 이 `true`
- [ ] `edge.msg_rejected_total` 이 **0 을 유지**한다 (하나라도 오르면 스키마 위반)
- [ ] `cameras[].sub_state` 가 `ok`, `fps` 가 **8.0 이상**
- [ ] `time_sync.edge_offset_ms` 가 숫자로 나오고 `edge_synced` 가 `true`
- [ ] NTP 를 일부러 끊었을 때 `edge_synced: false` + 화면에 「시각 동기화 실패」
- [ ] 대시보드 실시간 관제에 사람·지게차 박스가 **영상과 겹쳐** 보인다 (정합 ±100ms)
- [ ] 거리선의 숫자가 `nearby[].dist_m` 과 같다
- [ ] 안전모를 벗으면 3초 뒤 확정 → 방송, 다시 쓰면 10초 뒤 시정
- [ ] 사람이 가려졌다 다시 나타나면 재결합되고 **해소 타이머가 0부터** 다시 찬다
- [ ] 크롭이 작을 때(원거리) `helmet` 이 **생략**되고 타이머가 리셋이 아니라 멈춘다

### 5.2 ESP32

- [ ] `GET /system/status` 의 `mcu.online` 이 `true`, `last_seen` 이 갱신된다
- [ ] 위반 확정 시 **1초 이내** 경광등이 켜진다
- [ ] `fall` 이면 연속 부저(level 3), `manual` 이면 일반 주의 패턴
- [ ] 30초 이상 상태 발행을 멈추면 화면이 「보고 없음」으로 바뀐다

### 5.3 대조에 쓸 것

```bash
uv run tasks.py sim --case normal_resolve
```

```bash
uv run tasks.py mcu
```

시뮬레이터가 만드는 메시지와 실물이 만드는 메시지를 나란히 놓고 필드를 대조한다.
시나리오 22종은 `sim/cases/` 에 있고, 기대값은 `uv run tasks.py cases` 가 대조한다.

## 6. 자주 틀리는 것 모음

| 실수 | 결과 |
|---|---|
| 서브 스트림을 640×640 정사각으로 설정 | 정규화 좌표가 눌려 **오버레이가 통째로 어긋난다** |
| 엣지가 **메인** 스트림을 받아 추론 | 8fps 예산을 1080p 디코딩에 태운다. 추론은 **서브만** 본다 |
| 엣지가 영상을 서버로 중계 | 서버는 카메라에서 **직접** 받는다. 엣지가 보내는 건 메타데이터뿐이다 |
| 서브 해상도를 640×360 미만으로 | 사람이 프레임 높이 18% 미만이면 안전모 판정이 계속 보류된다 |
| 카메라 한 대가 끊겼는데 하트비트를 멈춤 | 서버가 **엣지 전체**가 죽은 것으로 본다. `sub_state` 만 내려야 한다 |
| `nearby` 를 빈 배열 대신 **생략** | 진행 중인 근접 이벤트가 **해소로 판정**된다 |
| `in_zone` 을 구역 밖일 때 **생략** | 스키마 거부 — `null` 을 실어야 한다 |
| `helmet` 판정 불가를 `"unknown"` 으로 | 스키마 거부 — **필드를 생략**해야 한다 |
| `anchor` 를 bbox 아래변 중앙으로 계산 | 포크가 뻗은 지게차에서 거리선과 거리 판정이 어긋난다 |
| 한 트랙의 두 위반을 배열 하나로 | 스키마 거부 — 메시지를 **유형 수만큼** 보낸다 |
| NTP 실패 시 `offset_ms: 0` · `synced: true` | **맞춘 적 없는 시계가 완벽한 것으로 보인다.** 클립이 조용히 밀린다 |
| ByteTrack 짧은 단절마다 `track_lost` | 이벤트가 계속 재결합 대기에 들어가 수명이 실제와 달라진다 |
| 디버그 필드를 임시로 얹음 | `extra="forbid"` — **그 프레임 전체가 거부**된다 |
| 임계값을 `config.yaml` 에 복사 | 현장에서 화면으로 바꾼 값과 어긋난 채로 돈다 |
