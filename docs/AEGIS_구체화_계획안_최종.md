# AEGIS 구체화 계획안
**자율 현장 대응형 AI 안전관제 시스템**
팀 AIM · 이시우 · 손서원 | 2026 포스코DX AI Youth Challenge

---

## 1. 프로젝트 개요

### 1.1 무엇을 만드는가

중소 제조현장의 CCTV 영상을 AI가 실시간으로 분석해 **안전 위반을 감지하고, 현장 스피커로 즉시 경고 방송을 내보내고, 실제로 시정되었는지까지 자동으로 확인하는** 시스템입니다. 여기에 축적된 위반 기록을 분석해 보고서를 작성하고 관리자의 질문에 답하는 AI 어시스턴트를 더했습니다.

### 1.2 왜 필요한가 — 대상 현장과 문제

**대상**: 상시근로자 5~50인 규모의 **중소 제조현장** (금속가공·기계·자동차부품 등 중량물을 다루고 지게차를 운용하는 사업장)

중대재해처벌법은 업종 예외 없이 **상시근로자 5인 이상 모든 사업장**에 적용되며, 50인 미만 사업장의 사고사망자는 건설업과 제조업에서 많이 발생합니다. 그러나 이 규모의 제조현장에는 **CCTV를 상시 감시할 전담 인력도, 관제 시스템을 도입할 예산도 없습니다.**

특히 제조현장의 가장 큰 위험 요인은 지게차입니다.

- **지게차는 고용노동부 기준 제조업 사망사고의 기인물 1위**이며, 최근 5년간 재해자 5,818명, 사망자 173명이 발생했습니다
- 주요 사고 유형은 **부딪힘·끼임·깔림**이고, 원인은 **적재 화물이 운전자 시야를 가리는 구조적 취약성**과 전진·후진 반복에 따른 후방 감시 소홀입니다
- 「산업안전보건기준에 관한 규칙」은 지게차 작업 시 **작업지휘자 또는 유도자 배치**와 **지게차 운행 경로와 보행자 통로의 물리적 분리**를 요구합니다

문제는 **영세 사업장에는 유도자로 배치할 인력이 없다는 것**입니다. 규정은 있으나 지킬 수단이 없는 상태입니다.

기존 상용 AI 관제 솔루션도 이 공백을 메우지 못합니다. 대형 사업장을 대상으로 한 고가 제품인 데다, 기능이 **"위험을 감지해 관리자에게 알림을 보내는 것"에서 끝나기** 때문입니다. 알림을 받아 현장에 지시할 사람이 없는 현장에서는 실효성이 없습니다.

### 1.3 우리의 접근

**감지에서 멈추지 않고 현장에서 직접 경고하며, 그 경고가 효과가 있었는지 숫자로 증명합니다.**

- 위반 감지 → 즉시 경고 방송(1초 이내) → 작업자가 시정하는지 계속 추적 → 시정 완료 판정
- 이 과정에서 **「방송 후 시정률」**(경고 후 실제로 시정된 비율)이 자동 집계됩니다
- 초기 하드웨어 100만 원 이내, 운영비는 사실상 0원
- 역할로 표현하면, **사람을 둘 수 없는 현장에 AI가 유도자를 대신 배치하는 것**입니다

## 2. 시스템 구성

### 2.1 세 개의 계층과 각자의 역할

시스템은 역할이 다른 세 부분으로 나뉩니다. 이해를 돕기 위해 사람 몸에 비유하면 다음과 같습니다.

| 계층 | 장비 | 비유 | 하는 일 |
|---|---|---|---|
| **Tier 0 · 엣지** | Jetson Orin Nano | **눈** | 영상에서 사람·지게차를 찾아내고 위치·거리·자세를 계산 |
| **Tier 1 · 메인 서버** | 노트북 (현장 내) | **반사신경과 기억** | 위반을 최종 판단해 즉시 경고를 발동하고 모든 기록을 저장 |
| **Tier 2 · 클라우드** | Google Gemini API | **생각하는 뇌** | 쌓인 기록을 분석해 보고서를 쓰고 질문에 답함 |

**"반사신경"이라 부르는 이유**: 사람이 뜨거운 것에 닿으면 뇌가 판단하기 전에 척수가 손을 빼듯, 이 계층은 **AI의 복잡한 추론을 거치지 않고 정해진 규칙으로 즉각 반응**합니다. 그래서 감지부터 경고 방송까지 1초 이내에 끝나고, 인터넷이 끊겨도 정상 작동합니다.

### 2.2 영상이 흐르는 두 갈래 길

CCTV 카메라는 같은 장면을 **두 가지 화질로 동시에 내보낼 수 있습니다**(메인/서브 스트림). 이 특성을 이용해 영상을 두 경로로 나눕니다.

```
IP 카메라 2대
 ├─ 고화질 1080p ─→ 메인 서버 : 관제 화면 표시 + 7일치 녹화
 └─ 저화질 640p  ─→ Jetson   : AI 추론용 (어차피 640으로 축소해 분석)

Jetson ─→ 메인 서버 : 영상이 아닌 "분석 결과"만 전송 (좌표·이벤트 정보, 수 KB)
```

**이렇게 나눈 이유**
- Jetson이 영상을 중계하지 않으므로 병목이나 고장 지점이 되지 않습니다. Jetson이 멈춰도 CCTV 관제 화면과 녹화는 계속됩니다
- 추론은 저화질로 충분하므로 Jetson의 부담이 줄어듭니다
- 증거로 남길 영상은 서버가 가진 고화질 원본에서 잘라내므로 화질 손실이 없습니다

### 2.3 하드웨어 구성 (총 997,420원 · 신청 완료)

| 부품 | 금액 | 역할 |
|---|---|---|
| Jetson Orin Nano Super 8GB | 445,000 | AI 추론 전용 소형 컴퓨터 |
| NVMe SSD | 301,500 | 7일치 영상 + 위반 클립 저장 |
| IP 카메라 ×3 | 157,800 | 주 시점 2대 + 예비 1대 |
| PoE 스위치 | 20,180 | 카메라·ESP32에 전원과 네트워크를 랜선 하나로 공급 |
| 스피커 | 21,900 | 경고 방송 출력 |
| ESP32-POE-ISO | 51,040 | 경광등·부저 제어용 소형 제어기 |

메인 서버는 팀이 보유한 노트북을 사용합니다. 경고음은 서버에 연결된 스피커로 내보내고, ESP32는 **설비 소음이 심해 방송이 잘 들리지 않는 구역**의 경광등·부저를 담당합니다. 제조현장은 상시 소음이 크기 때문에 시각 경보의 중요성이 건설현장보다 높습니다.

## 3. 감지 구조와 사용 모델

### 3.1 2단계 캐스케이드 구조

이번 설계의 핵심입니다. 감지를 한 번에 끝내지 않고 **두 단계로 나눕니다.**

```
프레임
 └─ [1단계] 객체 감지 : person, vehicle(지게차) 두 종류만 찾음
      ├─ vehicle → 추적 · 거리 계산 → 근접 판정
      └─ person  → 추적 · 위치 · 자세 판정
            └─ 사람 부분만 잘라냄 → [2단계] 분류 : 안전모 착용 여부 판정
```

**왜 이렇게 나눴는가**

1. **위반이 누구 것인지 명확해집니다.** 한 번에 안전모까지 감지하면, 작업자가 겹쳐 서 있을 때 그 안전모가 누구 것인지 판단할 수 없습니다. 사람을 하나씩 잘라내어 판정하면 **위반이 특정 작업자에게 정확히 귀속**됩니다.
2. **학습 데이터 준비가 훨씬 빠릅니다.** 분류는 잘라낸 이미지에 라벨만 붙이면 되므로, 안전모마다 네모 상자를 그리는 것보다 작업량이 적습니다.
3. **다른 보호구로 확장하기 쉽습니다.** 분류 모델의 클래스만 추가하면 보안경·안전화 등으로 넓힐 수 있습니다. 업종마다 요구되는 보호구가 다른 제조업 특성에 유리한 구조입니다.
4. **화면이 단순해집니다.** 상자는 사람과 지게차에만 그리고, 위반한 작업자의 상자를 붉게 표시합니다.

### 3.2 사용 모델

| 역할 | 모델 | 실행 위치 |
|---|---|---|
| 1단계 물체 감지 + 윤곽 추출 | **YOLO26-s-seg** (파인튜닝) | Jetson (GPU 상시) |
| 2단계 안전모 분류 | **YOLO26-cls** | Jetson (GPU, 크롭 단위) |
| 사람·지게차 추적 | **ByteTrack** | Jetson (CPU) |
| 거리 계산 | **호모그래피** (AI 아님, 좌표 변환 수식) | Jetson (CPU) |
| 3D 검증 | **Depth Anything V2 Small** | Jetson (GPU 간헐) |
| 장면 임베딩 | **Gemini Embedding 2** | 클라우드 API |
| 분석·보고서·대화 | **Gemini Flash** | 클라우드 API |
| 에이전트 제어 | **LangGraph** | 메인 서버 |

**정밀도 방침**: TensorRT **FP16**을 기본으로 합니다. 공식 벤치마크상 Orin Nano Super에서 INT8은 FP16보다 약 0.8ms 빠르지만 정확도(mAP)가 0.480에서 0.449로 떨어집니다. 속도 여유가 충분하므로 **정확도를 우선**하며, 실측에서 성능이 부족할 경우에만 INT8을 검토합니다.

**연산 여유**: 카메라 2대 × 8fps 기준 프레임당 예산은 62.5ms이고, 디코드·전처리·감지(세그멘테이션 포함)·마스크 후처리·분류·추적을 합한 실제 소요는 **약 30~57ms(예산의 50~90%)**로 추정됩니다. 성립하지만 여유가 넉넉하지는 않으므로, **마스크 후처리를 GPU에 유지하는 것이 성능의 관건**입니다. 안전 감지는 초 단위로 지속되는 사건을 다루므로 초당 30프레임이 필요하지 않으며, 실측이 부족할 경우 6fps 하향·모델 규모 축소·INT8 순으로 대응합니다.

※ 공개 벤치마크의 수 ms 단위 수치는 GPU에 적재된 텐서 기준 순수 추론 시간이며, 전처리·후처리를 포함한 실측치는 통상 그 3~4배입니다. 위 추정은 실측 보고치를 기준으로 했습니다.

## 4. 무엇을 감지하는가

| 감지 항목 | 판단 방법 | AI 학습 |
|---|---|---|
| **안전모 미착용** | 2단계 분류 모델 | 필요 |
| **금지구역 침입** | 사람 위치를 실제 좌표로 변환 → 구역 안팎 판정 | 불필요 |
| **지게차 근접(협착·충돌 위험)** | 사람↔지게차 실제 거리 + 깊이 검증 | 필요(지게차 클래스) |
| **쓰러짐** | 자세 기하 + 정지 지속 + 깊이 검증 | 불필요 |
| **미정의 이상 상황** | 평소 장면과 얼마나 다른지 수치 비교 | 불필요 |

**제조현장에 맞춘 이유**

- **지게차 근접**은 제조업 사망사고 기인물 1위 문제를 정면으로 겨냥합니다. 적재 화물로 시야가 가려 보행자를 못 보는 상황에서, 시스템이 대신 보고 경고합니다
- **금지구역**은 「산업안전보건기준에 관한 규칙」이 요구하는 **지게차 운행 경로와 보행자 통로의 분리**를 소프트웨어로 구현한 것입니다. 프레스·로봇 셀 등 고정 설비 주변 위험구역에도 동일하게 적용됩니다
- **쓰러짐**은 소규모 제조현장에서 흔한 야간·1인 작업 중 감전·질식·심정지 상황을 겨냥합니다. 발견이 늦으면 치명적입니다

## 5. 감지 로직 상세

### 5.1 금지구역은 어떻게 지정하고 판정하는가

**시스템이 바닥의 노란 선을 인식하는 것이 아닙니다.** 구역은 학습 대상이 아니라 **설정값**입니다.

1. 설치할 때 관리자가 대시보드에서 카메라 화면을 보며 **마우스로 위험 구역을 그립니다**(클릭 몇 번)
2. 그린 영역이 실제 지면 좌표로 변환되어 저장됩니다
3. 이후에는 "감지된 사람의 발 위치가 그 영역 안인가?"를 계산으로 판정합니다

**제조현장의 이점**: 공장은 설비 배치가 고정되어 있으므로 **한 번 그린 구역이 계속 유효합니다.** 매일 배치가 바뀌는 건설현장과 달리 재설정이 거의 필요 없습니다.

### 5.2 호모그래피 — 화면 속 픽셀을 실제 거리(m)로 바꾸는 방법

**호모그래피**는 AI가 아니라 기하학 수식입니다. 카메라가 고정되어 있고 바닥이 평평하다는 조건에서, **화면 좌표와 실제 지면 좌표 사이의 변환 규칙**을 구합니다.

- 설치할 때 바닥의 네 지점을 줄자로 실측해 입력하면 변환 행렬이 **한 번만** 계산됩니다
- 이후에는 사람의 발 위치 픽셀을 이 행렬에 넣기만 하면 **"지게차로부터 3.2m"** 같은 실제 거리가 나옵니다
- 연산량이 사실상 0에 가까워 매 프레임 계산해도 부담이 없습니다
- 지게차가 이동하면 그 픽셀 위치가 바뀌므로 **거리도 자동으로 갱신**됩니다. 재설정이 필요한 경우는 카메라를 옮겼을 때뿐입니다

오차는 설치 조건에 따라 10m 이내에서 10~30cm 수준입니다. 이를 흡수하기 위해 구역 경계에 여유 마진(0.3~0.5m)을 두며, 안전 용도에서는 **약간 일찍 경고하는 방향의 오차가 오히려 바람직**합니다.

**제조현장에서 유리한 점**: 지게차는 지면을 주행하는 장비이므로 바닥 접점이 명확합니다. 굴착기 붐처럼 공중으로 뻗는 부위가 없어 **지면 기준 거리 계산이 정확하게 성립**합니다.

### 5.3 거리 계산의 정밀화 — 사각형 상자에서 실제 윤곽으로

AI 감지 결과는 보통 **사각형 상자**로 나오는데, 이것만으로 거리를 재면 오차가 생깁니다. 사람이 다리를 벌리거나 지게차 포크가 앞으로 뻗으면 상자 모서리가 실제 물체와 동떨어진 지점을 가리키기 때문입니다.

YOLO26이 함께 출력하는 **윤곽선(마스크)**을 쓰면 해결됩니다.
- 사람의 발 영역을 정확히 짚어 지면 좌표로 변환
- 사람 윤곽과 지게차 윤곽 사이의 **가장 가까운 두 점의 거리** 계산 → 뻗은 포크와 작업자 사이의 진짜 최단 거리

개발 순서상 처음에는 사각형 상자 기준으로 구현하고, 이후 윤곽 기반으로 정밀화합니다.

### 5.4 깊이 추정 — 언제, 왜 쓰는가

**깊이(뎁스) 모델**은 사진 한 장에서 각 픽셀이 카메라로부터 얼마나 먼지 추정하는 AI입니다. 사람이 한쪽 눈만으로도 원근을 느끼는 것과 같은 원리입니다.

**항상 켜두지 않는 이유**는 직관과 반대입니다. **바닥에 서 있는 물체의 거리는 호모그래피가 더 정확합니다.** 호모그래피는 실측 기반이라 절대 거리가 정확한 반면, 깊이 추정은 학습에 기반한 "추측"이라 앞뒤 관계에는 강해도 절대 거리는 흔들립니다.

**깊이가 필요한 순간은 호모그래피가 헷갈릴 때**입니다.
- **원근 착시**: 화면상 사람과 지게차가 겹쳐 보이지만 실제로는 앞뒤로 떨어져 있는 경우
- **가림**: 설비나 적재물에 발이 가려 위치가 불확실한 경우 (실내 제조현장에서 특히 잦습니다)
- **자세 판정**: 쓰러짐 여부 확인 (5.5 참조)

따라서 다음 조건에서만 한 프레임 실행합니다.
- 계산된 거리가 위험 기준선 부근일 때 (명백히 안전하거나 명백히 위험하면 실행하지 않음)
- 두 물체의 화면 영역이 겹쳐 보일 때
- 발 위치 신뢰도가 낮을 때
- 쓰러짐 조건이 충족되었을 때

같은 대상에 대한 결과는 0.5초간 재사용해 중복 실행을 막습니다. 정리하면 **호모그래피가 상시 거리를 재고, 깊이 추정은 애매한 상황에서만 판정을 검증하는 심판 역할**입니다.

### 5.5 쓰러짐은 어떻게 판정하는가

학습 없이 **기하 정보와 시간 조건**으로 판정합니다. 아래 세 조건을 **모두** 충족해야 합니다.

| 조건 | 내용 |
|---|---|
| ① **높이 비율이 낮음** | 화면상 사람의 높이를, 그 거리에서 서 있을 때의 기대 높이와 비교합니다. 거리로 정규화하므로 멀든 가깝든 같은 기준이 적용됩니다 |
| ② **몸의 방향이 수평** | 사람 윤곽의 긴 축 방향을 계산합니다. 서 있으면 수직에 가깝고 누우면 수평에 가깝습니다 |
| ③ **움직임이 없는 상태가 지속** | **쭈그려 작업하는 사람은 상체와 팔이 계속 움직이지만, 쓰러진 사람은 움직이지 않습니다.** 오탐을 막는 가장 중요한 조건입니다 |

세 조건이 충족되면 **깊이 추정으로 한 번 더 검증**합니다. 서 있는 사람은 카메라로부터 거의 같은 거리에 있어 깊이 분포가 좁고, 바닥에 누운 사람은 깊이가 바닥을 따라 퍼져 분포가 넓습니다. 이 차이로 자세 판정의 신뢰도를 높입니다.

**경고 방식이 다릅니다**: 쓰러진 사람은 스스로 시정할 수 없으므로 "안전모를 착용하세요" 같은 시정 유도 방송은 부적절합니다. **경광등 점등과 관제 화면 최우선 알림, 관리자 확인 요청**으로 처리하며, 시정률 지표에서도 별도 집계합니다.

## 6. 실제 작동 흐름

### 6.1 평상시

1. 카메라 2대가 고화질은 서버로, 저화질은 Jetson으로 영상을 보냅니다
2. 서버는 관제 화면에 라이브 영상을 띄우고 7일치를 녹화합니다
3. Jetson은 매 프레임 사람과 지게차를 찾고, 추적 번호를 부여하고, 실제 거리를 계산해 **좌표 정보만** 서버로 보냅니다
4. 사람은 잘라내어 안전모 착용 여부를 판정합니다. 단 **착용 상태는 초 단위로 바뀌지 않으므로 판정 결과를 약 1초간 재사용**해 연산을 절약합니다
5. 관제 화면에는 라이브 영상 위에 감지 상자와 구역 표시가 겹쳐 보입니다

### 6.2 위반이 발생했을 때

**① 후보 발생 (Jetson)**
규칙에 걸리는 상황이 발견되면 "이벤트 후보"로 서버에 보고합니다.

**② 확정 (서버)**
서버는 곧바로 경고하지 않습니다. **같은 사람에게서 같은 위반이 몇 초간 계속되는지** 확인한 뒤 확정합니다. 순간적인 가림이나 오검출을 걸러내는 장치입니다.

**③ 확정 시 네 가지가 실행됩니다**
- **경고 발동** — 스피커 방송 + 경광등 (감지부터 여기까지 1초 이내)
- 데이터베이스에 이벤트 기록
- 녹화본에서 **고화질 캡처** 추출
- 클라우드로 캡처 이미지를 보내 **심층 분석 요청** (백그라운드, 실시간 경고를 지연시키지 않음)

**사건 전후 10초 클립**은 조금 뒤에 만들어집니다. 확정된 순간에는 "사건 이후" 구간이 아직 녹화되지 않았기 때문에, 추출 작업을 예약해 두었다가 10여 초 뒤에 실행합니다. 그동안 관리자 화면에는 캡처 이미지가 대신 표시됩니다.

**④ 시정 확인 (서버)**
경고 후에도 같은 작업자를 계속 지켜봅니다. 위반이 사라진 상태가 일정 시간 유지되면 **"시정 완료"**로 판정하고 이벤트를 종료합니다. 이때 **경고 시각과 시정 시각의 차이가 기록되어 「방송 후 시정률」과 「평균 시정 시간」이 집계**됩니다. 시정되지 않으면 일정 시간 후 다시 경고합니다.

**⑤ 작업자를 놓쳤을 때 — 지표를 정직하게 유지하는 장치**

작업자가 설비에 가리거나 화면 밖으로 나가면 추적 번호가 끊깁니다. 이때 그냥 이벤트를 닫아버리면 세 가지 왜곡이 생깁니다. ⑴ 안전모를 쓰러 갔다 온 사람이 시정으로 집계되지 않고, ⑵ 같은 위반이 두 건으로 나뉘어 경고가 중복되며, ⑶ 반대로 추적 번호가 다른 사람에게 넘어가면 시정하지 않았는데 시정한 것으로 잡힙니다.

그래서 시스템은 이렇게 처리합니다.

- 추적이 끊겨도 **15초간 이벤트를 살려둡니다**
- 그 사이 같은 자리 근처에 사람이 다시 나타나면 **같은 사람으로 이어 붙입니다.** 허용 거리는 경과 시간에 비례합니다 — 1초 만에 나타났으면 1.5m 이내, 8초 걸렸으면 5m까지
- 이어 붙였더라도 **곧바로 시정 처리하지 않고** 시정 조건을 처음부터 다시 확인합니다. 다른 사람이 번호를 물려받았을 가능성을 막기 위해서입니다
- 끝내 다시 찾지 못하면 **「판정 불가」**로 종결하고, **시정률 계산에서 아예 빼되 그 비율을 함께 표시**합니다

화면에는 **「방송 후 시정률 87% (판정 불가 5%)」**처럼 두 숫자가 항상 같이 나옵니다. 관측하지 못한 건을 시정으로도 미시정으로도 세지 않는 것이 통계적으로 정확하고, 지표를 외부에서 검증할 수 있게 만듭니다. 판정 불가율이 높다는 것은 카메라 위치가 부적절하다는 신호이기도 하므로 설치 품질을 진단하는 값으로도 쓰입니다.

### 6.3 관리자가 사용할 때

- 알림을 클릭하면 클립 영상과 AI 분석 내용을 확인
- 챗봇에 자연어로 질문 (통계·장면 검색·현재 상황 브리핑)
- 버튼 하나로 주간 안전 보고서 생성
- 대시보드에서 시정률·위반 추세·반복 위험 구역 확인

## 7. AI 지능 기능

### 7.1 두 종류의 AI를 역할에 따라 나눠 씁니다

- **임베딩 모델** = **찾고 비교하는 도구.** 장면을 3,072개의 숫자로 바꿔 두 장면이 얼마나 비슷한지 계산합니다. 설명은 하지 못합니다
- **LLM** = **읽고 쓰는 도구.** 상황을 해석해 문장으로 설명하고 보고서를 작성합니다

**Gemini Embedding 2**는 텍스트와 이미지를 **같은 벡터 공간**에 배치하므로, 한국어 문장과 영상 장면의 유사도를 직접 계산할 수 있습니다. 문장으로 장면을 검색하는 것이 가능해집니다.

### 7.2 임베딩으로 구현하는 기능

**① 자연어 영상 검색**
`"지난주 지게차 근처에서 안전모 안 쓴 장면 찾아줘"` 같은 질문에 해당 클립을 찾아줍니다. 감지 항목에 없는 상황도 검색됩니다.
※ `"안전모 위반 몇 건"`처럼 태그로 답할 수 있는 질문은 데이터베이스 조회가 더 정확하고 빠르므로, **조건은 DB로 먼저 좁히고 자유 문장 부분만 임베딩으로 순위를 매기는 방식**을 씁니다.

**② 반복 위반 자동 묶기**
비슷한 장면이 반복되면 하나로 묶어 "동일 위반 12회 반복"으로 집계합니다. 알림이 쏟아지는 것을 막고, 추적 번호가 끊겨 한 사건이 둘로 쪼개지는 문제도 보완합니다.

**③ 미정의 이상 상황 탐지**
평상시 장면을 **5분 주기로** 모아 "이 현장의 정상적인 모습" 기준을 만들어 둡니다. 이후 화면이 그 기준에서 크게 벗어나면 이상으로 표시합니다. **감지 항목에 정의하지 않은 위험**(적재물 붕괴, 연기, 야간 무단 출입 등)을 잡을 수 있는 유일한 경로입니다.
※ 오탐 가능성이 있어 **경고 방송은 하지 않고 대시보드 '주의' 알림으로만** 표시합니다. 이상이 감지되면 해당 화면을 LLM에 보내 "무엇이 평소와 다른지" 설명을 붙입니다.
※ 실내 제조현장은 조명이 일정해 옥외 현장보다 **오탐이 적고 기준선이 안정적**입니다.

**④ 유사 사고사례 자동 매칭**
KOSHA 사고사례집을 미리 벡터로 만들어 두고, 위반이 발생하면 유사한 과거 사고를 찾아 보고서에 근거로 인용합니다.

### 7.3 LLM이 하는 일 — "안전모 쓰세요"를 넘어서기

감지 결과만 전달하면 LLM은 뻔한 문장밖에 못 만듭니다. 그래서 **여러 정보를 하나로 합쳐서** 입력합니다.

```
위반 유형: 안전모 미착용 | 위치: 지게차 통행로
주변: 지게차 3.2m, 이동 중 | 지속: 45초
반복: 7일간 4회 | 이상 점수: 0.71
유사 사고: 지게차 부딪힘 사망사고 (KOSHA)
규정: 산업안전보건기준 규칙 제32조
```

**결과 출력 예시**
> "3번 작업자가 이동 중인 지게차 3.2m 이내에서 안전모 미착용 상태로 45초간 체류했습니다. 부딪힘과 낙하물이 겹치는 복합 위험 상황입니다. 최근 7일간 동일 위반이 4회 반복되어 개별 안전교육을 권고합니다. 유사 상황에서 과거 사망사고 이력이 있습니다."

**규정 매칭은 검색이 아닙니다.** 위반 유형별로 해당 법령 조항을 미리 표로 만들어 두고 정확히 연결합니다. LLM이 조항을 지어내는 것을 방지하기 위해서입니다.

**LangGraph**는 이 과정(분석 → 규정 연결 → 위험도 판단 → 문장 생성)을 단계별로 제어하는 도구이며, **메인 서버에서 실행**됩니다. 클라우드는 계산을 대신해 주는 도구일 뿐이고, 판단과 조합은 서버가 합니다.

### 7.4 관제 화면 구성 (7개 페이지)

| 페이지 | 내용 |
|---|---|
| **개요** | 시정률·오늘 위반·평균 시정 시간·이상 플래그, 추세 그래프, 시스템 상태 |
| **실시간 관제** | 2채널 라이브 + 감지 표시, 진행 중 이벤트, 수동 방송 |
| **이벤트** | 위반 목록·상태 추적 + 상세(클립, AI 분석, 유사 사례, 규정, 시정 타임라인) |
| **영상 검색** | 자연어로 장면 검색, 유사도순 클립 결과 |
| **분석·보고서** | 시정률 추이, 반복 위반 순위, 시간대 히트맵, 이상 탐지, 보고서 생성 |
| **챗봇** | 통계 질의·장면 검색·현장 브리핑 |
| **설정** | 금지구역 그리기, 캘리브레이션, 경고음 매핑, 임계값, 시스템 상태 |

화면에 그리는 상자는 **사람과 지게차뿐**입니다. 안전모는 별도 상자 없이 사람 상자의 색으로 표현합니다(정상=청록, 위반=적색, 쓰러짐=적색 점멸).

## 8. 차별성과 비용

### 8.1 차별성

시장 조사 결과 **자연어 영상 검색이나 보호구 감지 자체는 이미 상용 제품에 존재**합니다. 따라서 개별 기능이 아니라 **조합과 대상**으로 차별화합니다.

| 차별점 | 내용 |
|---|---|
| **① 시정까지 확인하는 완결 구조** | 상용 제품은 "감지 → 알림"에서 끝납니다. AEGIS는 직접 경고하고 시정 여부까지 자동 판정해 **경고의 효과를 숫자로 증명**합니다. 이 지표 체계는 조사한 어떤 솔루션에도 없었습니다 |
| **② 사람을 대신하는 유도자** | 규칙은 지게차 작업 시 유도자 배치를 요구하지만 영세 사업장에는 인력이 없습니다. AEGIS는 **규정이 요구하는 역할을 저비용으로 대체**합니다 |
| **③ 영세 현장 전용 · 저비용** | 하드웨어 100만 원, 운영비 0원 수준. 대기업 솔루션이 다루지 않는 5~50인 제조현장이 대상 |
| **④ 인터넷 없이도 안전 기능 유지** | 감지·경고·기록·시정판정이 모두 현장 내에서 완결. 원본 영상은 현장 밖으로 나가지 않음 |
| **⑤ 정의하지 않은 위험까지 포착** | 평상시와 다른 상황을 수치로 감지 + 유사 사고사례 자동 인용 |

> 발표 시 표현: *"개별 기능은 대기업 솔루션에도 있습니다. 하지만 이 가격에, 이 대상에게, 경고의 효과를 숫자로 증명하는 완결 구조는 없습니다."*

## 9. 개발 계획

### 9.1 개발 우선순위

**1순위 — 시스템이 성립하기 위한 필수 기능**
① Jetson 영상 처리 파이프라인(하드웨어 디코딩 + 추론 8fps) ② 1단계 감지 모델 학습(사람·지게차) ③ 2단계 안전모 분류 모델 학습 ④ 분류 결과 캐싱 ⑤ 사람·지게차 추적 ⑥ 호모그래피 + 금지구역 판정 ⑦ 이벤트 상태 관리(확정·경고·**시정 판정**) ⑧ 경고 발동 ⑨ 기록·클립 저장 ⑩ 관제 화면 3종

**2순위 — 감지 정밀화와 차별성 기능**
⑪ 지게차 근접 판정 ⑫ 윤곽 기반 정밀 거리 ⑬ 깊이 검증 ⑭ 쓰러짐 판정 ⑮ 임베딩·영상 검색 ⑯ LLM 분석 ⑰ 챗봇 ⑱ 분석 대시보드

**3순위 — 여유가 있을 때**
반복 위반 묶기, 이상 탐지, 사고사례 매칭, 보고서 자동 생성

> **감지 관련 기능(1·2순위)은 모두 구현 대상입니다.** 일정이 부족할 경우 3순위에서만 조정합니다.
> **위험요소 자연어 등록(오픈보캐블러리 제로샷)은 채택하지 않습니다.** 사전 검증에서 입력 이미지에 따라 지게차 감지 성능 편차가 커 신뢰성을 확보하지 못했고, 시연용 모형 대응을 위해 어차피 전용 학습이 필요하기 때문입니다. 감지는 파인튜닝된 `person`/`vehicle` 2클래스 단일 모델로만 수행하며, 대상 확장이 필요하면 재학습합니다. (기능명세서 부록 A-1)

**개발 전략 두 가지**
1. **하드웨어를 기다리지 않습니다.** 서버 개발은 처음부터 미리 녹화한 영상을 CCTV처럼 재생해 진행하므로, 부품 수급이 늦어져도 일정이 밀리지 않습니다.
2. **마지막 구간에는 기능을 추가하지 않습니다.** 시연에서 중요한 것은 기능 개수가 아니라 안정성입니다.

### 9.4 시연 계획 (1m × 1m 모형 제조현장)

미니어처 공장을 제작하고 카메라 2대를 설치해 실제 시스템을 그대로 구동합니다. 지게차 모형, 설비 모형, 바닥에 표시한 보행자 통로와 위험구역으로 구성합니다.

1. 안전모를 씌우지 않은 인형을 지게차 통행 구역에 배치 → **1초 내 경광등·경고 방송·화면 알림**
2. 안전모를 씌워 이동 → **자동 시정 판정 → 시정률 수치 상승**
3. 지게차 모형을 작업자 쪽으로 접근 → **근접 경고** (실제 거리 표시)
4. 인형을 눕혀 쓰러짐 상황 연출 → **긴급 알림 + 관리자 확인 요청**
5. 챗봇에 질문 → 과거 유사 장면 검색·클립 재생
6. 보고서 생성 → 규정·사고사례가 인용된 문서 출력

**대비책**: 실제 현장에서 촬영한 영상을 CCTV처럼 재생하는 모드를 함께 준비해, 모형에 문제가 생겨도 시연이 가능하며 실환경 동작의 증거로도 활용합니다.

### 9.5 성과 측정 지표

- **감지 정확도**: 정밀도(오탐률), 재현율(놓침률)
- **분류 정확도**: 안전모 착용/미착용 판정 정확도, 판단 불가 비율
- **응답 속도**: 감지부터 경고 방송까지의 시간(ms)
- **방송 후 시정률**: 경고 후 일정 시간 내 시정된 비율 ← **핵심 차별화 지표**
- **판정 불가율**: 추적 단절로 시정 여부를 관측하지 못한 비율. 시정률과 **항상 병기**하며, 추적·설치 품질의 대리 지표로도 사용
- **평균 시정 시간**: 경고부터 시정까지 걸린 평균 시간
