# AEGIS

중소 제조현장(상시근로자 5~50인)의 CCTV 영상을 AI로 실시간 분석해 안전 위반을 감지하고,
현장 스피커로 즉시 경고 방송을 내보내고, **실제로 시정되었는지까지 자동으로 확인**하는 시스템.

팀 AIM (이시우 · 손서원) · 2026 포스코DX AI Youth Challenge

---

## 무엇이 다른가 — 「방송 후 시정률」

상용 안전관제 제품은 **감지 → 알림**에서 끝난다. 알림을 보낸 뒤 현장이 실제로 고쳤는지는
아무도 모른다. AEGIS는 경고 방송 이후를 계속 추적해 이 숫자를 만든다.

```
방송 후 시정률 = 시정됨 / (시정됨 + 늦은 시정 + 미시정)
판정 불가율    = 추적 끊김 / (위 셋 + 추적 끊김)
```

**두 숫자는 항상 함께 표시한다.** 추적이 끊긴 이벤트는 「시정하지 않은 것」이 아니라
**「시정 여부를 관측하지 못한 것」**이다. 미시정으로 세면 성능이 부당하게 낮아지고,
시정으로 세면 지표가 부풀려져 근거를 댈 수 없다. 모집단에서 빼되 그 비율을 공개하는 것이
통계적으로 정확하며 외부 검증이 가능한 형태다.

분모가 0이면 비율은 `0%`가 아니라 `–`다. `0%`는 "아무도 시정하지 않았다"는 주장이지만
실제로는 "판정할 이벤트가 없다"이기 때문이다.

## 감지하는 것

| 유형 | 판정 방식 |
|---|---|
| 안전모 미착용 | 사람 크롭 → 2단계 분류 (전용 bbox 없음, 사람 박스 색으로 표현) |
| 금지구역 침입 | 접지점이 구역 폴리곤 안인가 (지면 좌표 기준) |
| 지게차 근접 | 마스크 최근접 거리 — 포크가 뻗은 형상까지 반영 |
| 쓰러짐 | 학습 없이 기하 3조건 **모두** 충족 시에만 |

쓰러짐 3조건은 높이비 · 마스크 PCA 주축각 · **정지 지속**이다. 세 번째가 오탐 억제의
핵심이다 — 쭈그려 앉기와 허리 굽혀 작업은 앞의 둘을 통과하지만(실제로 낮고 실제로
기울어져 있다) 상체가 계속 움직이므로 세 번째에서 걸린다.

**감지 클래스는 `person` · `vehicle` 2종 고정이다.** 제로샷/오픈보캐블러리는 쓰지 않는다.

**영상은 듀얼 스트림으로 분리된다.** 1080p 메인은 서버가(라이브·7일 녹화·클립 원본),
640p 서브는 엣지가(추론) 받는다. 엣지는 영상을 중계하지 않고 **메타데이터만** 보낸다.
젯슨이 멈춰도 관제 화면과 녹화는 살아 있다.

두 스트림의 화면비는 반드시 16:9로 같다. 엣지가 서브에서 정규화 좌표를 내고 대시보드가
그것을 메인 위에 그리므로, 다르면 박스가 한쪽 축으로 눌린다.

## 설계 원칙

이 저장소가 일관되게 지키는 규칙들이다. 코드 곳곳의 주석이 그 근거를 담고 있다.

**시간을 직접 읽지 않는다.** `datetime.now()` 금지. `Clock` 프로토콜을 주입받는다.
테스트가 3초·10초·15초·30초·300초 타이머를 순간이동시켜야 하므로, 이 규칙이 깨지면
검증 자체가 불가능해진다.

**엣지는 판단하지 않는다.** 규칙에 걸리면 후보만 올리고 확정·경고·시정판정은 전부
서버가 한다. 시뮬레이터도 같은 규칙을 지킨다.

**거리 수치는 항상 호모그래피 값을 쓴다.** 단안 뎁스는 절대거리가 부정확하므로 앞뒤
분리 판별과 깊이 분산 확인에만 쓴다. 그래서 뎁스 결과 객체에는 **미터 필드가 아예 없다** —
필드를 없애는 것이 "쓰지 마라"보다 강하다.

**가드가 조용히 꺼지지 않게 한다.** 훅·검증·테스트는 실패했을 때 반드시 드러나야 한다.
예외를 삼키거나, 도구 부재를 건너뛰거나, 실패를 `exit 0`으로 덮지 않는다.
**실행할 수 없으면 통과가 아니라 오류다.**

**스키마는 `packages/contracts`에만 정의한다.** 서버·프론트·엣지·시뮬레이터가 같은
정의를 공유하며, TypeScript 타입은 거기서 생성된다.

**정책값은 DB `policies` 테이블에서 읽는다.** 임계값·타이머를 코드에 하드코딩하지 않고,
관리자가 화면에서 조정하면 **재시작 없이** 진행 중인 이벤트에도 즉시 반영된다.

## 실행

개발 환경은 **Windows + PowerShell**과 **macOS** 양쪽에서 동작한다. `make`와 셸 스크립트를
쓰지 않고 모든 태스크를 `tasks.py`에 모았다 — 젯슨(리눅스)에서도 같은 명령이 돈다.

```bash
uv run tasks.py dev        # docker-compose + 마이그레이션 + 서버 + 프론트
uv run tasks.py cams       # 가짜 RTSP 4경로 송출 (실물 카메라가 없을 때)
uv run tasks.py sim --case <이름>   # 가짜 엣지
uv run tasks.py mcu        # 가짜 ESP32
```

실물 장비를 붙일 때:

```bash
uv run tasks.py relay      # 실물 IP 카메라 → mediamtx
uv run tasks.py edge       # 실물 엣지 러너 (모델 추론)
```

관제 화면 <http://127.0.0.1:5173/live> · API 문서 <http://127.0.0.1:8000/docs>

### 검증

```bash
uv run tasks.py verify
```

11단계를 실행한다 — 타입 생성 정합 · lint · format · mypy · pytest · 마이그레이션 ·
서버 부팅 스모크 · 프론트 타입체크 · vitest · 빌드.

**명령을 찾을 수 없어 건너뛴 것을 통과로 간주하지 않는다.** 각 단계는 실제로 실행되어야
하며, 실행할 수 없으면 통과가 아니라 오류로 보고한다.

```
파이썬 테스트   826건
프론트 테스트    30건
```

시나리오 기대값 대조는 따로 있다:

```bash
uv run tasks.py cases      # 12종 시나리오의 시정률·판정불가율·경고·클립 상태를 표로 대조
```

## 핵심 수치

| 구분 | 값 |
|---|---|
| 카메라 메인 / 서브 | 1920×1080 · 15fps / 640×360 · 15fps (둘 다 16:9) |
| 모델 입력 | 640×384 rect letterbox |
| 엣지 처리 | 카메라당 8fps 이상 |
| 확정 / 해소 지속 | 3초 / 10초 |
| 재경고 쿨다운 | 30초 |
| 트랙 소실 유예 / 재결합 창 | 15초 / 10초 |
| 시정 인정 창 | 300초 |
| 클립 전·후 구간 | 각 10초 |
| 녹화 보존 | 7일 순환 |
| 확정 → 경고 | 1초 이내 |
| 오버레이 정합 오차 | ±100ms |

위 값은 **기본값**이며 전부 DB `policies`에서 읽는다.

## 기술 스택

**서버** Python 3.13 · FastAPI · SQLModel · PostgreSQL + pgvector · alembic · paho-mqtt
**엣지** ONNX Runtime / TensorRT · OpenCV · 2단계 연결 추적기(ByteTrack 방식, 자체 구현)
**프론트** React 18 · TypeScript · Vite · WebRTC(WHEP) / hls.js
**인프라** Docker Compose · mediamtx · mosquitto
**지능** Google Gemini (임베딩 · LLM) · LangGraph
**도구** uv · ruff · mypy · pytest · vitest
