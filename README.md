# AEGIS

**중소 제조현장의 CCTV를 안전관리자 한 명처럼 만드는 시스템.**

이미 달려 있는 CCTV 영상을 실시간으로 보고, 안전모를 안 쓴 작업자나 지게차에 너무 가까이
선 사람을 찾아내고, 현장 스피커로 **즉시 경고 방송**을 내보내고, 그 사람이 **실제로
고쳤는지까지 끝까지 지켜본다.**

대상은 **상시근로자 5~50인 규모의 중소 제조현장** — 금속가공·기계·자동차부품처럼 중량물을
다루고 지게차를 운용하는 사업장이다. 중대재해처벌법은 업종 예외 없이 5인 이상 모든
사업장에 적용되고 50인 미만에서 사고사망자가 많이 나오지만, 이 규모에는 **CCTV를 상시
감시할 전담 인력도, 관제 시스템을 도입할 예산도 없다.** 이미 달려 있는 CCTV를 그대로 쓴다.

팀 AIM (이시우 · 손서원) · 2026 포스코DX AI Youth Challenge

## 어떻게 도는가

```
 ①  감지          ②  확정            ③  경고             ④  시정 확인
 ───────────      ───────────        ───────────         ───────────
 CCTV 영상에서     3초 이상 계속       사전 녹음된 음성을    같은 사람을 계속 추적해
 안전모·거리·      유지되면 위반으로   현장 스피커로 방송   위반이 사라졌는지 본다
 자세를 계산       확정한다            + 경광등·부저        10초 유지되면 시정
                                                          300초 넘으면 늦은 시정
```

**②의 3초와 ④의 10초가 이 시스템의 뼈대다.** 스쳐 지나가는 순간을 위반으로 세지 않고,
잠깐 가려진 것을 시정으로 세지 않는다. 그 사이 같은 사람을 놓치지 않으려고 추적이
끊기면 15초까지 기다렸다가 다시 이어붙인다.

경고가 나갔는데도 안 고치면 30초마다 다시 방송한다. 확정 시점 앞뒤 10초는 클립으로
잘라 남긴다 — 나중에 사람이 판정을 확인할 수 있어야 하기 때문이다.

## 왜 이 시스템인가 — 「방송 후 시정률」

위 ④가 이 프로젝트의 전부다. 상용 안전관제 제품은 **감지 → 알림**에서 끝난다. 알림을
보낸 뒤 현장이 실제로 고쳤는지는 아무도 모르고, 그래서 **이 숫자가 존재할 수 없다.**

관리자가 실제로 알고 싶은 것은 「오늘 위반이 몇 건이었나」가 아니라
**「경고가 실제로 먹혔나」**다. AEGIS는 그 숫자를 만든다.

```
방송 후 시정률 = 시정됨 / (시정됨 + 늦은 시정 + 미시정)
판정 불가율    = 추적 끊김 / (위 셋 + 추적 끊김)
```

**두 숫자는 항상 함께 표시한다.** 추적이 끊긴 이벤트는 「시정하지 않은 것」이 아니라
**「시정 여부를 관측하지 못한 것」**이다. 미시정으로 세면 성능이 부당하게 낮아지고,
시정으로 세면 지표가 부풀려져 근거를 댈 수 없다. 모집단에서 빼되 그 비율을 공개하는 것이
통계적으로 정확하며 외부 검증이 가능한 형태다.

분모가 0이면 비율은 `0%`가 아니라 `–`다. `0%`는 "아무도 시정하지 않았다"는 주장이지만
실제로는 "판정할 이벤트가 없다"이기 때문이다.

## 감지하는 것

| 유형 | 판정 방식 |
|---|---|
| 안전모 미착용 | 사람 크롭 → 2단계 분류 (전용 bbox 없음, 사람 박스 색으로 표현) |
| 금지구역 침입 | 접지점이 구역 폴리곤 안인가 (지면 좌표 기준) |
| 지게차 근접 | 마스크 최근접 거리 — 포크가 뻗은 형상까지 반영 |
| 쓰러짐 | 학습 없이 기하 3조건 **모두** 충족 시에만 |

쓰러짐 3조건은 높이비 · 마스크 PCA 주축각 · **정지 지속**이다. 세 번째가 오탐 억제의
핵심이다 — 쭈그려 앉기와 허리 굽혀 작업은 앞의 둘을 통과하지만(실제로 낮고 실제로
기울어져 있다) 상체가 계속 움직이므로 세 번째에서 걸린다.

**감지 클래스는 `person` · `vehicle` 2종 고정이다.** 제로샷/오픈보캐블러리는 쓰지 않는다.

## AI 구성

AI를 두 층으로 나눈다. **엣지는 실시간이라 안전 판정을 맡고, 클라우드는 느려도 되는
분석을 맡는다.** 클라우드가 죽어도 안전 루프는 그대로 돈다.

### 엣지 — Jetson Orin Nano · TensorRT FP16

| 모델 | 하는 일 |
|---|---|
| **세그멘테이션** (YOLO seg) | `person` · `vehicle` 마스크. 640×384 rect letterbox |
| **안전모 분류** (YOLO26n-cls) | 사람 크롭 128×128 → `on` / `off` |
| **Depth Anything V2 Small** | 사람과 지게차가 겹쳐 보일 때 **앞뒤 분리** 판별 |
| **추적** (2단계 연결) | 높은 신뢰도로 트랙 시작, 낮은 신뢰도로 잇기만 |

**마스크를 쓰는 이유**가 있다. 지게차 근접은 박스 중심 거리가 아니라 **마스크 최근접
거리**로 잰다 — 포크가 뻗은 형상에서 중심 거리는 3.7m인데 최근접은 1.4m라, 위험 반경
3.0m를 사이에 두고 판정이 뒤집힌다.

**뎁스는 거리를 내지 않는다.** 단안 뎁스는 절대거리가 부정확하므로 「앞뒤로 갈렸는가」와
「깊이가 퍼져 있는가」만 답한다. 그래서 결과 객체에 **미터 필드가 아예 없다** — 필드를
없애는 것이 "쓰지 마라"보다 강하다. 거리는 항상 호모그래피 값을 쓴다.

**항상 돌지 않는다.** 뎁스는 회색지대·화면 겹침·접지점 신뢰도·쓰러짐 후보 네 조건 중
하나라도 걸릴 때만 부른다. 하나도 안 걸리면 모델을 호출조차 하지 않는다.

### 클라우드 — Google Gemini · LangGraph

| 기능 | 내용 |
|---|---|
| **자연어 장면 검색** | 「지난주 1번 카메라 안전모 미착용」 → 기간·카메라·유형은 SQL로 먼저 좁히고, 남은 문장만 벡터로 순위 매김 (하이브리드) |
| **키프레임 임베딩** | 확정 이벤트의 키프레임을 `halfvec(3072)`로. pgvector에 저장 |
| **LLM 심층 분석** | LangGraph 4단계 — `collect → embed → similar → analyze` |
| **유사 사고사례** | KOSHA 사례와 코사인 유사도. 확정 시 1회 계산해 저장 |
| **규정 매핑** | 산업안전보건기준 조항 연결 |
| **챗봇** | 질의를 `sql` · `vector` · `vision` 세 경로로 라우팅 |
| **현장 브리핑** | 「지금 상황은?」에 현재 프레임을 보고 답함 |
| **이상 탐지** | 5분마다 프레임을 임베딩해 같은 시간대 「평소」와 비교 (k-NN 평균 코사인 거리) |
| **주간 보고서** | 집계는 SQL이 만들고 LLM은 문장으로 옮김 |

### 이 층에서 지킨 것

**규정 조항을 LLM이 생성하지 않는다.** 위반 유형 → 조항은 **사전 구축 테이블**로
연결한다. 없는 조항을 그럴듯하게 지어내면 그 문서는 법적 근거가 될 수 없다.

**이상 탐지는 경고 방송을 발동하지 않는다.** 조명·물건 위치만 바뀌어도 점수가 오르기
때문이다. 스피커가 그걸로 울리면 현장이 **경보를 무시하는 법을 배우고**, 그 순간
시정률이 의미를 잃는다. 화면에 앰버 「주의」로만 뜬다.

**보고서의 숫자는 SQL이 만든다.** LLM은 그것을 문장으로 옮길 뿐이다. 챗봇도 도구가
돌려준 값만 쓰고, 도구를 부르지 않고 통계를 말하지 않는다.

**이상 탐지는 판정 여부와 무관하게 샘플을 쌓는다.** 이상이었던 프레임을 빼면 「정상」의
정의가 스스로 좁아져 나중엔 무엇을 봐도 이상이 된다.

**클라우드 키가 없어도 서버는 뜬다.** 규정 매핑과 SQL 통계는 그대로 돌고, 화면은
「지능 기능 없음」과 「서버가 그 경로를 모름」을 구분해 보여준다.

## 관리자가 보는 화면

| 화면 | 하는 일 |
|---|---|
| **개요** | 오늘의 시정률·위반 건수·평균 시정 시간, 구성요소 상태 |
| **실시간 관제** | 라이브 영상 위에 박스·거리선·금지구역. 진행 중인 이벤트, 수동 방송 |
| **이벤트** | 위반 목록과 상세 — 클립 재생 · 시정 타임라인 · 규정 조항 · 수동 정정 |
| **영상 검색** | 「지난주 1번 카메라 안전모 미착용」처럼 문장으로 장면 찾기 |
| **분석·보고서** | 시정률 추이 · 유형 분포 · 시간대 히트맵 · 반복 위반 · 주간 보고서 |
| **설정** | 캘리브레이션 · 금지구역 그리기 · 경고 음원 · 임계값 |

라이브 화면의 박스는 **도착 즉시 그리지 않는다.** 영상(1080p 메인)과 좌표(640p 서브 →
엣지 → 서버)는 경로가 달라 지연이 다르므로, 즉시 그리면 박스가 사람보다 앞서 움직인다.
좌표를 시각 기준 지연 버퍼에 담았다가 **재생 중인 프레임 시각에 맞춰** 꺼내 그린다.
정합 목표는 ±100ms다.

지능 기능(장면 검색 · LLM 분석 · 챗봇 · 이상 탐지)은 클라우드를 쓰지만 **꺼져도 안전
루프는 그대로 돈다.** 인터넷 없는 현장이 정상 운용 조건이다.

**영상은 듀얼 스트림으로 분리된다.** 1080p 메인은 서버가(라이브·7일 녹화·클립 원본),

그것을 메인 위에 그리므로, 다르면 박스가 한쪽 축으로 눌린다.

## 설계 원칙

이 저장소가 일관되게 지키는 규칙들이다. 코드 곳곳의 주석이 그 근거를 담고 있다.

**시간을 직접 읽지 않는다.** `datetime.now()` 금지. `Clock` 프로토콜을 주입받는다.
테스트가 3초·10초·15초·30초·300초 타이머를 순간이동시켜야 하므로, 이 규칙이 깨지면
검증 자체가 불가능해진다.

**엣지는 판단하지 않는다.** 규칙에 걸리면 후보만 올리고 확정·경고·시정판정은 전부
서버가 한다. 시뮬레이터도 같은 규칙을 지킨다.

**거리 수치는 항상 호모그래피 값을 쓴다.** 단안 뎁스는 절대거리가 부정확하므로 앞뒤
분리 판별과 깊이 분산 확인에만 쓴다. 그래서 뎁스 결과 객체에는 **미터 필드가 아예 없다** —
필드를 없애는 것이 "쓰지 마라"보다 강하다.

**가드가 조용히 꺼지지 않게 한다.** 훅·검증·테스트는 실패했을 때 반드시 드러나야 한다.
예외를 삼키거나, 도구 부재를 건너뛰거나, 실패를 `exit 0`으로 덮지 않는다.
**실행할 수 없으면 통과가 아니라 오류다.**

**스키마는 `packages/contracts`에만 정의한다.** 서버·프론트·엣지·시뮬레이터가 같은
정의를 공유하며, TypeScript 타입은 거기서 생성된다.

**정책값은 DB `policies` 테이블에서 읽는다.** 임계값·타이머를 코드에 하드코딩하지 않고,
관리자가 화면에서 조정하면 **재시작 없이** 진행 중인 이벤트에도 즉시 반영된다.

## 실행

개발 환경은 **Windows + PowerShell**과 **macOS** 양쪽에서 동작한다. `make`와 셸 스크립트를
쓰지 않고 모든 태스크를 `tasks.py`에 모았다 — 젯슨(리눅스)에서도 같은 명령이 돈다.

```bash
uv run tasks.py dev        # docker-compose + 마이그레이션 + 서버 + 프론트
uv run tasks.py cams       # 가짜 RTSP 4경로 송출 (실물 카메라가 없을 때)
uv run tasks.py sim --case <이름>   # 가짜 엣지
uv run tasks.py mcu        # 가짜 ESP32
```

실물 장비를 붙일 때:

```bash
uv run tasks.py relay      # 실물 IP 카메라 → mediamtx
uv run tasks.py edge       # 실물 엣지 러너 (모델 추론)
```

관제 화면 <http://127.0.0.1:5173/live> · API 문서 <http://127.0.0.1:8000/docs>

### 검증

```bash
uv run tasks.py verify
```

11단계를 실행한다 — 타입 생성 정합 · lint · format · mypy · pytest · 마이그레이션 ·
서버 부팅 스모크 · 프론트 타입체크 · vitest · 빌드.

**명령을 찾을 수 없어 건너뛴 것을 통과로 간주하지 않는다.** 각 단계는 실제로 실행되어야
하며, 실행할 수 없으면 통과가 아니라 오류로 보고한다.

```
파이썬 테스트   826건
프론트 테스트    30건
```

시나리오 기대값 대조는 따로 있다:

```bash
uv run tasks.py cases      # 12종 시나리오의 시정률·판정불가율·경고·클립 상태를 표로 대조
```

## 진척

| | | |
|---|---|---|
| **M0** | 뼈대와 계약 | ✅ |
| **M1** | 인프라와 통로 — 스트리밍·녹화·WebSocket | ✅ |
| **M2** | 엣지 인터페이스와 이벤트 생성 · 오버레이 정합 | ✅ |
| **M3** | 상태머신과 지표 — 확정·해소·재결합·시정률 | ✅ |
| **M4** | 경고와 클립 — 방송·경광등·예약 추출·클라우드 격리 | ✅ |
| **M5** | 관제 화면 P0 | ✅ |
| **M6** | 설정과 좌표계 — 캘리브레이션·구역·정책 | ✅ |
| **M7** | P1 감지 정밀화 — 근접·쓰러짐 3조건·뎁스 | ✅ |
| **M8** | 지능·분석 — 임베딩·장면 검색·챗봇·이상 탐지 | ✅ |
| **M9** | 엣지 실물 이식 — Jetson TensorRT · 실물 카메라 · ESP32 | ✅ |

기능명세서 P0·P1 전량이 구현되어 있다. FN-ID별 코드 위치와 테스트 매핑은
[`docs/INDEX.md`](docs/INDEX.md)에 있다.

**시뮬레이터는 전 구간에서 실물로 교체됐다.** 실물 IP 카메라 2대가 mediamtx로 들어오고,
Jetson Orin Nano가 TensorRT 엔진으로 추론해 `/ws/edge`로 후보를 올리며, ESP32가 MQTT로
경광등·부저를 받는다. `sim/`은 회귀 검증용으로 남아 있다 — 시나리오 12종이 시정률과
판정 불가율까지 기대값과 대조한다.

## 핵심 수치

| 구분 | 값 |
|---|---|
| 카메라 메인 / 서브 | 1920×1080 · 15fps / 640×360 · 15fps (둘 다 16:9) |
| 모델 입력 | 640×384 rect letterbox |
| 엣지 처리 | 카메라당 8fps 이상 |
| 확정 / 해소 지속 | 3초 / 10초 |
| 재경고 쿨다운 | 30초 |
| 트랙 소실 유예 / 재결합 창 | 15초 / 10초 |
| 시정 인정 창 | 300초 |
| 클립 전·후 구간 | 각 10초 |
| 녹화 보존 | 7일 순환 |
| 확정 → 경고 | 1초 이내 |
| 오버레이 정합 오차 | ±100ms |

위 값은 **기본값**이며 전부 DB `policies`에서 읽는다.
